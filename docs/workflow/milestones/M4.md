## Invariants (quoted in review requests)
- **G1** Render-thread cost of publication is one atomic exchange per block and one pointer
  assignment when a layout arrives. No allocation, lock, wait, I/O or logging is added to
  `render`, event dispatch or `reset`.
- **G2** Render never reads a layout after it has stored that layout's successor in
  `adopted_revision`. The control owner frees a layout or an instance only after it reads
  `adopted_revision` ≥ the revision that dropped it.
- **G3** One layout in flight. A second publish waits for adoption, bounded by three block
  periods; a stopped stream is swapped quiescently.
- **G4** Unchanged by M4: event ordering and budgets, the ingress and egress rings' ordering
  guarantees, clock anchors, parameter smoothing, feedback block size, poly rules, the FTZ/DAZ
  guard, and every existing module's behaviour when its descriptor does not use a new field.
- **G5** Additions to `module2.h` are at the end of their structs, guarded by `struct_size`. A
  module built against the header before the addition loads and behaves the same.
- **G6** With no edit in a render, output is bit-identical: golden 24 identical on three
  platforms on every PR. E4b and E5 change what an edit sounds like and nothing else.
- **G7** `adopt` and the data-slot read are realtime code: bounded, no allocation. `adopt` keeps
  no pointer into the old instance. A data pointer is valid for one `process` call.
- **G8** Instruction counts: no row more than 1 % worse on E6, E4a, E5, E3a, E7. E4b may cost up
  to 3 % on rows with ramping-capable edges, stated in the PR with the rows; more is an escalation.

## Task notes
- **E6:** the amount leaves the edge's identity (sort order, the delay-line match and the replan
  key compare edges without it). The amount travels as a host packet to the edge; a 5 ms smoother applies it. With no
  amount change the smoother is bypassed, so golden is identical. `setModAmount` stops building a
  candidate graph. Continuity row `setModAmount`: every witness at the section 9 gate.
- **E4a:** no behaviour change. Golden identical, continuity rows unchanged within repeat noise,
  instruction counts per G8. This PR exists so that E4b's diff is only the behaviour change.
- **E4b:** 0005 section 5 "Publication" and "Ramps" are the specification. Only the engine's
  park state machine and its fade are removed. The facade's master fade in `app_engine` (the
  `loadGraph` and stopped-stream path) stays as it is. Required tests:
  (1) unit tests of ramp arithmetic and of an edit arriving during a transition; (2) a stress
  test that applies at least 10,000 random valid edits against a rendering engine on the null
  path under ThreadSanitizer and AddressSanitizer with zero reports; (3) continuity rows for
  every `swap` command and for `applyGraph` with one structural change. The known latency
  compensation limit of section 5 gets its own probe row and is reported, not gated.
- **E5:** section 7. Voice-count change uses this path. `Engine::reconfigure` has no production
  caller today; E5 builds on the replan branch that creates a new instance for a changed config,
  and removes `reconfigure` and its tests if nothing else then uses it. Tests: a module with `adopt` keeps phase
  and held notes across a config change; one without rings out under the fade and receives the
  held notes again; `replace_fade_ms` is honoured and clamped to 500.
- **E3a:** section 6. `setData {moduleId, slot, value}` is `live` class; `applyGraph` delivers
  changed `data` the same way and does not list the module in `replaced`. A full ring is `busy`.
  The packed block is validated against the field table off the audio thread; a bad value is a
  refusal that names the field. Data present in a document is packed and delivered by the shared
  loader, so `loadGraph` and the web build get it without a second implementation; live `setData`
  in the web build's own dispatcher is out of scope and the web build stays green.
- **E3b / E3c:** the module reads its slot every block and keeps no copy. Existing documents
  that hold the same content in `config` load unchanged through a one-way read in the document
  loader (config → data), with a test per module. Groove's Apply-while-stopped restriction is
  removed in Studio.
- **E7:** today `setSampleRate` and `setBufferFrames` stop the stream and rebuild the engine from
  the document, so every instance is new (`session.cpp`). Two rules. (1) A buffer size that is
  not larger than the block size the engine was prepared for keeps the engine: the stream
  restarts, nothing is rebuilt. (2) Otherwise the rebuild carries state: with the stream stopped,
  each instance's `save_state` is read, and after the rebuild `load_state` is given to the
  instance with the same ID, type and config. A module without `save_state` starts fresh and is
  named in the reply. Before code, the builder posts on the issue which modules implement
  `save_state` and what `selectAudioDevice` rebuilds today. Assumptions: **C1** `save_state` and
  `load_state` may be called per instance on a stopped engine and on a freshly prepared one;
  **C2** after a sample-rate change a module may refuse or adapt its state, and a refusal is not
  an error. A false C1 is a question. Continuity rows `setBufferFrames`, smaller and larger: held
  note and tail witnesses not silent after the stream resumes for modules with state; clock slip
  reported. The gap length on real devices is device-only and goes to the owner's Pi run.
- **CN:** the harness gains `applyGraph` rows, a `setData` row per data user, a `setTransport`
  row (0008) and the latency-compensation probe. Facts only, no thresholds in the harness.

## Escalate

row outside G8; a need to change event ordering or the rings; a module header change that `0012`
does not state; a false C1; a module whose tail cannot be kept by rule (2) and that the owner would notice (list it, do not redesign); a gate row that fails after two correction rounds, with the numbers.
