## Rulings (Fable, r1)

**R1 — T0.8 latency (answers Q1).** The probe reports three named quantities, never a single
"latency":
1. `harness_loopback_ms`: the harness plays a click and captures it through the cable in one duplex
   stream; latency is the sample-index difference divided by the sample rate. No wall clock.
2. `command_to_capture_ms`: monotonic time of the command write to the engine, to the onset in the
   captured signal. The onset time is the capture buffer's ADC timestamp plus index/rate. If the
   audio API gives no ADC timestamp, use callback time and add one capture-buffer duration to the
   stated uncertainty.
3. `command_to_sound_ms` is reported only as a **range**:
   `command_to_capture_ms − harness_loopback_ms` ≤ value ≤ `command_to_capture_ms`.
Each run records sample rate, buffer sizes, device names class (not host names), repeats ≥ 20,
median and p95. Onset detector and range arithmetic are unit-tested on synthetic signals. Accepted
as T0.8 when tool, tests and runbook step exist; the measured numbers come from an owner run.

**R2 — T0.5 impulse and tail (answers Q2).**
- *Impulse:* after reset and 1 s of silence, one sample of 1.0 on the module's audio input, driven
  through the offline engine path, at 44.1, 48 and 96 kHz, 2 s captured. Report peak, time to
  −60 dB re peak (ms), and NaN/Inf count. Modules with no audio input are `n/a`.
- *Tail and denormals:* production means the engine's own process path, which sets FTZ and DAZ
  (`native/engine2/engine2.cpp:857-862`). Measure through that path. Drive 1 s of signal, then
  5 s of silence; report (a) count of subnormal output samples, (b) median cost of a silent-tail
  block divided by median cost of an active block, 5 repeats. A probe that calls a module outside
  the engine sets the same flags itself and says so in the fact file. A flags-cleared run may be
  added as a separate, labelled column; it is information for non-FTZ targets, not acceptance.
- Timing ratios from hosted runners are advisory facts. No threshold, no gate.
