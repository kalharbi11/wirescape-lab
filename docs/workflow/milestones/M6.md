**Outcome:** anyone can point one command at one module folder and, with no test code of their own, get a static check,
the standard test matrix and an offline WAV with a summary. Each failure says what is wrong, where, and how to fix it.
No product file changes.

`--patch` give no authority here.

## Invariants (quoted in each review request)
1. Only `tools/module/runner/abi_ws2.h` includes `module2.h` or names a `ws2_`/`WS2_` identifier. A grep proves it.
2. Only `tools/module/layout.json` holds repo-relative paths. Python and C++ hold none, and no machine path is written into output.
3. No file outside the allowed paths changes. Reuse is by import or include path only (`helpers.discover_toolchain`,
   `probe.symbol_flags`, `test_banned_includes.BANNED`, `metrics.*`, `allocation_watch.*` or a tool-owned counter).
4. Devices off: no audio/MIDI/LAN API is linked or called. The runner links only the module, the C++ stdlib and the counter.
5. Deterministic: same folder, commit and platform give byte-identical `--json` for `check` and `test` (CPU fields only in `render`).
6. No AI, network or download at run time. Python 3 stdlib + C++17 compiler + CMake (+ ninja or VS). numpy/scipy are optional and
   only for two render fields.
7. Every FAIL and WARN has non-empty WHAT, WHERE and FIX from `messages.json`. A raw assert or stack trace is a tool bug.
8. C6, T10 and T13 never change the exit code in v0.
9. SPDX GPL-3.0-only on every new file. Runner sources that a later PR may move into `sdk/` are written MIT-compatible
   (MIT-licensed copies are flagged in the PR).
10. Facts under `facts/modules/` are neutral: commit, machine, date, command, result. Nothing is ranked or recommended.

## Acceptance
1. MT1–MT5 merged. `python tools/module/wsmod.py test native/sdk/template --json` exits 0 in quick and `--full` on the
   module-tools workflow for Linux x64, Linux ARM64 and Windows x64. Quick wall time is recorded per platform.
2. **Mutation suite:** ≥1 mutant per test T1–T9, T11, T13 and check C1–C3. Each is a patch on a temp copy of
   `native/sdk/template` (e.g. `new float[8]` in process; a static counter; reset that skips a member; save that omits a field;
   `#include <vector>`; NaN pass-through; initial > max; per-block coefficient). Each mutant yields exactly its expected test id
   FAIL (or WARN for T13) with the expected WHAT, and every other test unchanged. Unmutated template: 0 FAIL. This runs on all
   three platforms.
3. **Stock sweep:** `check` and `test --full` run on all 34 stock modules on the three platforms. `facts/modules/stock_v0.{json,md}`
   lists each module × test result. Every FAIL, WARN, `build_unsupported` (expected: macro_oscillator) or refusal (Chord
   without config, Macro at 44.1/96k) is listed as a fact with its message. **None is fixed in this milestone.**
4. `render` of the template with a tone writes a WAV that `bench/offline/metrics.read_audio` loads, and gives the summary
   fields. The clicks and alias fields are shown both present (numpy installed) and `unavailable` (not installed).
5. Invariant 1–2 greps and the "no product file changed" diff (`git diff --stat <base>..<head>`) are pasted in each PR.
6. `tools/module/README.md` gives an author the three commands, the exit codes and how to read a message, in ≤1 page.

## Escalate
A needed edit to any locked path or to `native/sdk` (including making it self-contained); a stock module that cannot
be compiled in place without a native CMake edit other than macro_oscillator; a test whose pass rule would fail ≥ one third of
stock modules (the rule is likely wrong: record the distribution as a fact, keep the test warn-only, and ask); any need for a non-stdlib Python dependency in check/test;
two failed correction rounds.
