## Invariants (quoted in the E1a review request)
- **J1** No change to `Engine`, `AppEngine`, `Session::commit`'s swap logic or any realtime path.
  The handler calls `commit(patch, false)` and then sends parameter events.
- **J2** `loadGraph` behaviour and replies are byte-identical; `applyGraph` is advertised as a
  capability and is purely additive to protocol v0.
- **J3** A refused `applyGraph` leaves graph, document and `gen` untouched, as for other swaps.
- **J4** Semantics 1–6 of 0005 section 3, each with a protocol test on the null sink: a continuing
  module keeps state (shown with a counter or phase that would reset), a changed config is listed
  in `replaced`, a changed parameter arrives, a removed-then-restored ID is accepted.
- **J5** Unknown document fields are preserved exactly as for `loadGraph`.
