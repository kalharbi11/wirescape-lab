  and the web bridge does not advertise the capability; the web build stays green.
- **TR2:** K1 and K3. Both new controls default to today's behaviour, so golden stays 24
  identical. Module tests show a synced Clock and a host-tempo Groove following a beat that the
  test drives directly through `ws2_process`; no engine change is needed for that. Clock's `sync`
  is appended with the next `legacy_index`. The S0 catalogue snapshot changes by that parameter
  only, shown as a diff in the PR.
- **TR3:** 0008 decisions 8 and 9. `FakeEngine` implements `setTransport` and reports it in status.
- **MB:** 0009 L1–L5. The tree has more hand lists than 0009 names; they are in scope:
  `native/io/midi/CMakeLists.txt` (the MIDI trio), the catalogue sources in `native/web/CMakeLists.txt`,
  the two SDK example `module.json` files, the readers in `bench/{gate,golden,portability,sdk}/`,
  `.github/workflows/portability.yml` where it parses a module's CMake file, and the two module
  guides under `docs/`. `osc.out` is missing from `known_module_ids.txt` today; generating the
  list adds it, which 0009 decision 5 allows. A `module.json` field the descriptor lacks is an escalation (L1). A golden
  difference on MB2 is an escalation (L2), never a declared sound change.
  **A97, L1 field classes (run 49):** MB1's equality test proves every catalogue field (ID, name, `abi_version`,
  ports, parameters, ranges, defaults, flags) equal between descriptor and `module.json`. Four manifest
  fields are not descriptor data and need no ABI change: `schema_version` is the file format and goes
  with the file; `library` must equal `ws2_<folder>` (asserted, then generated from the folder per 0009
  decision 1); `license`, where present (30 of 36), must equal the SPDX identifier in the folder's `module.cpp` (asserted); and
  `description` (23 manifests) moves to the first line under the title of the folder's `README.md` in
  MB2, before `module.json` is deleted, with a test that each string survives (MB2 creates the README
  where a folder has none, e.g. `poly_split`). No tool reads
  `description` or `license` from the manifests today. A runtime consumer of either (a Studio browser
  tooltip, the Player) would overturn this and needs a descriptor field under the 0003 module API work.
  `known_module_ids.txt` is generated from `wire-describe` (0009 decision 5), not from a bench set: every
  registered ID, experimental ones included (Gate Delay, `osc.out`). The list only grows; removing an
  experimental module later is an Architect ruling.
- **V1:** first a fact file `facts/code/native_v1_readers.md` (class A, any builder, may be filed
