## Confirmed nested path/device transport and qualified observations

**Graph document device fields:** Both engine-group `loadGraph.patch` and `applyGraph.patch` carry an entire JSON patch. For a `midi.in` module, the native config validator permits string `config.endpoint` and `config.system_name`, and MIDI subscriptions read these to select an endpoint. Consequently **two engine-group commands can carry a MIDI device name transitively**, despite R1's stated no-device-name engine-group guarantee. This is an observed field-flow, not a runtime device-use measurement or proposed modification. Sources: [native/document/runtime_module_config.h:376–383](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/document/runtime_module_config.h#L376-L383), [native/control/midi_host.cpp:12–28](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/control/midi_host.cpp#L12-L28), [native/sidecar/session.cpp:1225–1235](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/sidecar/session.cpp#L1225-L1235).

**OSC transport fields inside those graph patches:** `osc.in.config.port`, `config.lan`, and `config.rows[].pattern` are network bind/OSC pattern data; `osc.out.config.port`, `config.rows[].address`, and `config.notes.address` are destination-port/OSC address data. An OSC address is **not** a filesystem path. Explicit `osc.out.config.host` and `config.lan` input keys are **rejected** by the current loader (not accepted host names). The source inspection did not open sockets. Sources: [native/document/runtime_module_config.h:210–268](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/document/runtime_module_config.h#L210-L268), [native/document/runtime_module_config.h:294–366](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/document/runtime_module_config.h#L294-L366).

**Open document fields / unresolved value types:** The patch schema admits opaque `settings` fields, `modules[].config`, `preserved`, `host_mappings[]`, `devices[]` and additional unknown object keys. Sidecar `Session::execution` uses the full patch, and the `commit` path serializes that document. These keys may **transit** via both graph commands, but arbitrary nested key names and caller-supplied values cannot be enumerated by static schema inspection; their actual file-path or device semantics are **unresolved**. No arbitrary key is asserted to have been executed as a path. Sources: [docs/specs/patch_v2_draft.schema.json:7–36](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/docs/specs/patch_v2_draft.schema.json#L7-L36), [docs/specs/patch_v2_draft.schema.json:102–112](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/docs/specs/patch_v2_draft.schema.json#L102-L112), [native/sidecar/session.cpp:634–647](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/sidecar/session.cpp#L634-L647), [native/sidecar/session.cpp:707–721](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/sidecar/session.cpp#L707-L721).

**Direct device fields in host command requests:** `selectAudioDevice.deviceId` and `setMidiEnabled.deviceId` are the two request types directly carrying a device selection ID. Native audio IDs are host-API-qualified; MIDI selections resolve to `name`/`system_name`. Queries `listAudioDevices` and `listMidiDevices` do **not** carry device identifiers in their requests, but return Device entries containing IDs, names, host/API/system metadata. Sources: [native/sidecar/session.cpp:1091–1108](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/sidecar/session.cpp#L1091-L1108), [native/sidecar/session.cpp:1149–1160](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/sidecar/session.cpp#L1149-L1160), [docs/specs/ENGINE_PROTOCOL.md:119–123](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/docs/specs/ENGINE_PROTOCOL.md#L119-L123), [docs/specs/protocol.schema.json:207–277](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/docs/specs/protocol.schema.json#L207-L277).

**Naming distinctions:** `ccMap.set.mapping.channel/controller` are MIDI control selectors, not host endpoint identity ([native/sidecar/session.cpp:1273–1289](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/sidecar/session.cpp#L1273-L1289)). `applyGraph.result.path` is `live` or `restart`, not a filesystem path ([native/sidecar/session.cpp:965–967](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/sidecar/session.cpp#L965-L967)). `midiLearn` takes only `armed`; its `status.midi.learn.deviceId` can appear on an outbound observation ([native/sidecar/session.cpp:1351–1372](https://github.com/kalharbi11/wirescape-lab/blob/96e97a7b7f77d9c04feeedd5c08e094c11b41ab5/native/sidecar/session.cpp#L1351-L1372)).
