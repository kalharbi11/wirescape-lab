## Fixture identity and negative test boundary

- `native/examples/Six_Essentials_Demo.json:2–5,89–138` is the **native** v1 example: `format="wirescape.native.patch"`, `version=1`, `outputNode`, and old cable keys. The five other `native/examples/*.json` files at this pin have native patch version 2; `native/document/ui_starters.json` has fifteen patch-version-2 entries. The v1 example is supplied to the loader tests, offline play, document soak and golden renderer above.
- `native/tests/fixtures/legacy_documents/patch_v1.json:2–17` is the different `format="wirescape.patch"` (inspection-only) v1 fixture. `native/document/runtime_patch_tests.cpp:61–73` iterates it with other legacy/visual/future/malformed fixtures and asserts the native runtime loader **refuses** execution with a diagnostic and unchanged bytes/catalogue. This is not a successful native-patch-v1 load.
- `native/document/runtime_module_config.h:72–117` and `native/document/groove_runtime_tests.cpp:728–798` handle **Groove config** v1/v2; `native/modules2/**` `load_state` versions refer to **module state**, not patch format. These are separate version namespaces.
